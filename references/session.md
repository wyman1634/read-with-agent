# 带读、推进与换会话

## 开始带读

读取本书已有记录，用一句话接上当前位置，再开始一个阅读单元：解释本段的核心问题与论证，给出可就地展开的关键原文，用书中例子示范概念怎样起作用。需要互动时，优先围绕眼前的原文或 Agent 提供的完整情境邀请讨论；有明确待答任务时等回应后再反馈。

个人经历是可选的迁移材料，读者主动提及时接住；默认开场采用无需搜索个人记忆的例子。读者说“想不出来／没经历”时，Agent 提供情境并示范分析，再让读者选择讨论、换例子或继续听解释。这只说明案例暂不可得，不能据此判断概念没懂。人文带读按需要提问，也可以连续解释一小段，给读者随时打断的空间；每段不必以问题结尾。

思想书接住读者的解释、异议或实际案例，指出已经说清的部分和一个值得再想的断点；技术书依据真实预测、代码或实验，卡住先给提示；文学依据文本讨论。问题是帮助理解的邀请，读者可以换方向或跳过。

技术读者追问术语或指出概念关系缺失时，按 technical.md 的“概念与关系先于判断”修补当前讲解，再决定是否需要检查，不直接继续出题或套用应用提示。

## 同一会话怎么推进

| 读者输入 | 带读动作 | 记录方式 |
| --- | --- | --- |
| 回答、提出异议或给出案例 | 针对回应反馈，必要时补一个断点；当前问题已有足够依据时，推荐下一小段 | 记录实际回应、能支持的理解范围和未解决处 |
| 继续 | 接上当前单元尚未展开的解释或下一步；若仍有未答问题，可用一个新例子往前讲，不机械重复催答 | 保留未答问题，不能补记已理解 |
| 下一节、先往前读 | 转入路线中的下一单元，允许暂缓当前讨论 | 保留旧问题；注明选择向前，不等于掌握旧单元 |
| 没懂、换个例子 | 找出具体断点，换一个贴近读者的例子或回看关键原文 | 记录尚未理解的地方，不重讲全书 |
| 想不出经历、没有案例 | 提供一个完整情境，先示范概念如何用于分析，再邀请可选讨论或继续解释 | 记录案例暂不可得；理解状态按实际证据判断 |
| 改选某一节 | 采用最新兴趣方向，按需读取该节原文 | 更新当前入口，不补记中间章节完成 |
| 今天到这里、下次继续 | 保存当前单元、实际讨论、未答问题和下一步，给出换会话指令 | 不把结束会话当作完成学习 |

每次实质互动后更新当前进度摘要，原话与详细反馈保存到对应历史单元，偏好变化更新 preferences；按 workspace.md 保持各自简短或按需加载。将路线入口同步到最新位置，默认重建页面，用户本轮只想聊天时先更新 Markdown。保存前核对指定工作区，测试反馈不进入真实阅读记录。

## 新对话接着读

页面提供可复制指令，至少包含 `$read-with-agent` 与本书工作区的实际路径。新对话可用：

```text
$read-with-agent 继续带读这个工作区：<本书工作区路径>
```

新会话按 workspace.md 的恢复步骤读文件，简述当前位置和未完成事项，直接开始相应小段；无需用户复述旧对话，也不重新询问已保存的目标。只说“继续”但没有可见书籍上下文时，先检查当前目录的 reading／outputs/reading；只有一个明确工作区则复用，有多个候选时只问继续哪本。

路径只有在新会话能访问文件时才足以恢复。换机器或环境时携带整个书籍工作区（含所需 source），按新路径生成页面／指令；来源暂不可访问时，依据已保存内容回顾并说明缺口。
