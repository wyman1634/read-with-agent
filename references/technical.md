# 技术书：以表现验证理解

围绕读者实际要做的事建立知识结构：概念与机制、依赖关系、代码行为、适用条件与典型误区。记录书中软件版本，必要时用官方文档核对与当前环境的差异，分别标注书中原行为和当前行为。

## 全书地图与模块切换

1. 建立地图前核查整本书所有可用正文及图片；记录来源定位、检查方法、已核查和无法核查范围。不得把目录、自动提取或图片OCR冒充逐图分析；有缺口时显式标记待核查。来源有限时只建立覆盖现有材料的地图，说明缺失。
2. 建立全书主题→模块→知识点地图和清单，知识点关联一处核心讲解、所有相关原文章节、讲解目标、计划深度和必要前置；区分原书、当前版本及补充。完整识别全书内容后提出系统带读、简述或按需的范围，暂缓/跳过须经读者确认。网页是优先展示形态，材料文件是可维护的数据；地图/清单须可展开和回查来源。

   已准备结构化地图并采用单页地图展示时，按 [map-reader.md](map-reader.md) 准备数据并生成页面；它不会自动代替原书分析或历史复核。
3. 带读前交付地图供读者审阅；等待读者确认详略、顺序及入口。默认沿书的章节顺序，读者主动选择其他顺序时遵循其选择。旧书复核历史：具体知识点已讲则记已带读，章节或模块仅部分讲解记进行中，尚无已讲记录记待带读；链接具体证据。来源和历史仍有不确定时另行说明证据范围，不新增“待核对”进度状态。已有充分讲解不重复，缺口仅补必要内容。
4. 每轮标明主题、模块、知识点、原书位置和模块内进度；讲解并示范。分别记录带读状态（待带读、进行中、已带读、经确认暂缓）和理解证据（无反馈、自述理解、实际回答或实验），不据“继续”推断理解。已带读表示该知识点已实际讲过；模块或主题完成表示已确认范围内的知识点均已带读，相关追问已处理，不要求考试、实操或读者自述理解。
5. 模块或主题结束时对照清单报告已讲、未完成及下一入口，询问读者是否需要精讲或进入所指下一模块；等待明确回复。此前普通“继续”只推进当前模块；仅在该边界问题之后“继续”才确认所指切换。跨章、跨主题关联只引用既有核心讲解，避免重复。追问按session.md保留原位置，补讲后回主线。

已有地图只有目录级入口或全书蒸馏未完成时，明确记录缺口和剩余工作，不把标题当成完整知识点清单。若读者已明确选择从某入口开始，进入每个模块前对照正文、必要图片和历史补齐该模块清单，已讲与未讲分别记录；模块完成前逐项对照。分模块补齐不代表全书地图已完成，继续保留全书核查待办。相关前置已讲不等于目标小节已讲；仅有前置时保留关联入口，不据此标目标小节进行中。

## 路线先有领域关系图

**全书章节地图与领域关系图分开维护。** 目录能说明在哪一章读到一个词，不能替代这个词属于什么、和谁关联的框架。首次技术带读、进入新的主题家族，或旧工作区只有章节表而当前关系框架缺失时，先用已读正文或明确标注的补充来源，建立支撑当前路线的最小关系图，展示给读者并保存到 `map.md`；已有可用关系图则复用。

图中按本书领域区分容易混淆的层次，例如类型与实例、对象与属性、配置记录与执行程序。当前核心概念各有用途和带语义的关系，必要时按用途归类，并区分当前展开、后续待读与来源待核对的部分。这是随阅读扩展的框架，不是所有类型的穷举清单；后续家族可只留用途位置，不能用一串未解释的新名字补总图，也不能把图中出现过记为已掌握。

`route.md` 按概念依赖安排先后：先有当前领域框架，再补本单元的对象关系、解释机制、示范，最后才邀请可选应用。为当前入口注明它在关系图中的位置、依赖哪些前置，以及缺失时先补哪一段。无需等整张图全部掌握再推进，也不按目录顺序越过必要前置。

每轮引入当前推理依赖的新概念时，用简短定位说明它在已有框架中的类别、用途和连接的已知概念；简单新联系用文字或表格回填 map.md，已有图足够时直接复用。维护框架不等于每轮新增或重绘图片，需要制图时按 [visuals.md](visuals.md) 判断。跨会话通过进度指针读取相关部分，不重读或重讲整张图。若读者反复问“它也是某种对象吗”“到底有多少类”“学到这里仍没全貌”，先暂停原计划，检查并修复关系图和路线依赖，而不只再追加一个术语定义。记录中保留被暂缓的原下一步及真实理解证据。

**路线验收**：章节表之外，读者能在当前所需的关系图中定位本轮概念；原文阅读单元的前置在路线里有解释入口，尚未展开的名字没有被当成已知条件。未满足时先补框架或调整路线，不靠继续堆例子推进。具体示例再按下节检查。

## 控制展开深度，完成后回到主线

- 进入主题时按书中范围与读者目标确定本阶段要解决的核心问题和足够理解主线的深度；先讲主干和一个必要示例。标明原书内容、当前版本核对和 Agent 延伸，避免把扩展当作书的篇幅。
- 每次准备追加前置、边界或新示例前判断：它是否直接解决当前问题、解释刚出现的困惑，或避免影响结论的关键误解？是则只补到能接回主线；否则记为可回查的延伸，进入原路线下一点。允许以说明“此处先不展开”收束，不为列举分支连续创建新课程。
- 收束条件是核心问题已解释、有足以理解的例子，且当前用户追问已回应；不要求用户通过测试或已掌握全部边界。保留未答问题和未经验证的理解状态。多轮追问修补后检查是否已经偏离原路线，明确接回；读者说“继续”是推进信号，不等于授权自动展开更多变体。
- 读者要求深入、具体边界影响当前结论、目标确需更高深度，或读者尚未理解必要主干时，按实际需要继续讲；不要用固定轮数或篇幅截断必要解释。每次选取深度结合用户当前要求和本书偏好。

## 概念与关系先于判断

每轮准备讲解、示例、问题或操作命令时，先完成以下前置检查。检查由 Agent 根据阅读记录完成，不让读者先填一套基础问卷。

1. **找出依赖**：列出读懂本轮因果或完成任务所必需的概念与关系，对照记录，区分尚未介绍、仅提过名字、已解释和有实际应用证据。高级目标、相邻概念已懂、Agent 曾写出术语、读者说“继续”，都不能补作前置已讲清的依据。
2. **补齐新概念**：缺少介绍依据的概念，先在当前例子中说明它是什么类型、做什么、与已知对象怎样关联；必要时用最小结构图或字段片段区分相邻概念。一个中文译名、“逻辑分组”等抽象定义、字段注释或含有该术语的命令，都不能替代对象关系。只补支撑本轮推理的深度，已知部分直接复用，不递归展开整套课程。
3. **补齐情境**：说明决定结论的初始状态、执行主体、触发动作与先后顺序。涉及资源或配置对象时，交代它对应的实际资源从哪里来、由谁在何时准备；区分声明对象的创建、执行者的动作和实际资源的变化。涉及配置修改时分清本地编辑、一次提交和多次提交。介绍一种手段时，说明本例为什么需要它，并检查更简单的做法是否已足够。只讲影响结论的条件，边界紧随相应结论，不堆无关前提。
4. **先示范再邀请应用**：用完整情境展示这些对象如何产生结果，再给可选判断、配置改动或小实验。示范命令标明用途和预期，实际操作需要的环境与步骤也须已交代；代码出现本身不等于读者已经会用。

**输出验收**：读者应能仅根据本轮讲解和已记录的前文理解当前例子、推导所问结果或知道所给操作在做什么。涉及资源流程时，Agent 先检查能否据此回答“资源从哪里来、谁创建什么、谁执行、最后谁使用什么”；缺少依据时先核对来源。一次一小段按完整因果过程划分，必要环节在本轮补齐；可缩小到一种有明确前提的情境，把不影响当前结论的分支留后。若仍依赖未解释的核心名词、对象关系、隐藏条件或操作步骤，本轮先补讲或缩小范围，不能直接要求判断、配置或实操。无需把内部检查逐项展示、每段强制出题、取得“懂了”确认或通过考试；前置已足以支撑下一小段时可以继续，应用能力仍按真实证据记录。

容易遗漏的区别：

| 场景 | 应先交代的前置 |
| --- | --- |
| 跨命名空间访问服务 | Namespace 是独立资源；Pod/Service 通过 namespace 字段归属，Label 是属性。再解释短服务名的搜索范围，之后才适合判断名字或改配置。 |
| 用 pause 合并模板修改 | 明确示例是多次独立提交到集群，中间模板可能被观察；若一次提交完整模板，为合并修改不需要 pause。 |
| 用 PV/PVC 解释持久化 | 可先限定静态供应：管理员先准备实际存储卷，创建 PV 登记它，PVC 声明需求，控制器匹配绑定，Pod 经挂载使用该卷。说明本例实际卷已存在；动态供应另有创建卷的流程，PV 字段本身不代表后端已完成分配。 |

读者问“这个词是什么”“它也是某种已知对象吗”“为什么需要这一步”“资源从哪里来”时，先定位讲解缺口，暂停原来的练习或操作要求。连续追问同一过程时，回到同一个具体情境，把遗漏环节接回完整过程，再回到原例或原计划。记录缺失的前置与已补内容，把下一步改为概念修补，不能把讲解断层记成读者能力缺陷。前置足够但应用卡住时，再采用下面的提示与检查方式。

## 用实际表现检查应用

遵循读者互动偏好。读者希望只讲解和示范、需要时主动提出练习时，不主动安排或反复询问实验、练习；应用能力无证据则记录未验证。读者要求检查时，仅覆盖当前章节必要前置，选择能区分理解与误解的小任务。

提交任务后等待用户回答。卡住先给针对性提示；需要时提供解答和原因。运行示例记录真实命令、结果与环境，不把预期输出写成已执行结果。Agent 自己跑通只证明例子可运行，不能证明读者已掌握。

用户可以跳过练习，记录未验证。依据具体薄弱点调整路线；只说“懂了”时记自述理解。一个知识点在当前任务上有证据掌握，也不推断整章或全书均已掌握。
